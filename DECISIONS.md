# Architecture and Engineering Decisions

- D001: Selected Hono over Express/Fastify for server routing because of lightweight TypeScript-first ergonomics and native web standards support.
- D002: Selected better-sqlite3 with WAL mode for local derived cache because of synchronous speed, zero-network latency, and embedded simplicity.
- D003: Picked `models/gemma-4-26b-a4b-it` via Google AI Studio's OpenAI-compatible endpoint as the capable chat model after querying live `/models` endpoint (evaluated 26b vs 31b; 26b avoids free-tier rate spikes while having excellent instruction following).
- D004: Standardized single LLM client on OpenAI-compatible API without vendor-specific SDKs to allow seamless swapping between Google AI Studio and Ollama.
- D005: Designed synthetic monorepo seed script to be fully deterministic with PRNG seed (1337) generating 3,000 files across 40 directories and 200 commits in a bare git repo.
- D006: Clipped maximum blob diff and file size sent to LLM at 8KB with explicit truncation header to avoid context limit overflow and high token cost.
- D007: Added dual SQLite engine adapter supporting better-sqlite3 (production/Docker) and Node built-in node:sqlite (Windows/Node 24 development) with zero API divergence.
- D008: Validated LLM outputs using strict Zod schemas with 2 retries, falling back to deterministic heuristic parsing flagged is_degraded=1 to guarantee zero downtime.
- D009: Implemented `canopy digest` enforcing exactly two lines + risk flags, and added bilingual support (English and Bengali via --lang bn).
- D010: Added 64KB diff input limit and 8KB context window truncation with user notice to prevent LLM context exhaustion.
- D011: Served responsive light/dark Web UI directly from Hono server without heavy SPA frameworks to enable zero-build client delivery and instant cold boots on Render.
- D012: Enforced 60 req/min per-IP rate limiting and a 200,000 daily token cap with automated degradation to protect production demo API quotas.
- D013: Packaged application in multi-stage Docker container with auto-seeding on boot in ~1.5s, satisfying Render's sub-60s boot health requirement.
- D014: Authored Infrastructure-as-Code Blueprint (`render.yaml`) and exact 3-click manual deployment guide (`DEPLOY.md`) as standard fallback protocol.
- D015: Automated live verification suite (`scripts/verify-live.ts`) validating `/healthz`, lazy file fetch, 175.5x cold vs warm digest speedup, and rate limit response.
- D016: Added SQLite PRAGMA busy_timeout = 5000 to eliminate transient database lock failures under high concurrent write load.
- D017: Patched validateSafeRev to forbid revision arguments starting with a hyphen (-) to prevent command option injection into git CLI invocations.
- D018: Guarded getFile to verify git object type is a blob via `cat-file -t` and reject directory tree paths with HTTP 400.
- D019: Enforced public read-only mode (PUBLIC_READONLY) by returning HTTP 403 Forbidden on write/mutation endpoints.
- D020: Fixed CLI binary entrypoint in bin/canopy.js and server compiled entrypoint in dist/server/index.js with robust main module detection.
- D021: Re-recorded demo walkthrough to 86.2 seconds and generated 0.91 MB demo.gif using system ffmpeg, fulfilling 60-90s duration and <10MB GIF requirements.
- D022: Upgraded Dockerfile to node:22-slim with built-in node:sqlite (--experimental-sqlite), bound HTTP listener explicitly to 0.0.0.0, pre-seeded synthetic repo at Docker build time (<50ms boot), and added .dockerignore.
- D023: Removed platform-locked @rollup/rollup-win32-x64-msvc from devDependencies (causing EBADPLATFORM on Linux npm install), omitted optional native builds in Docker, added npm prune --omit=dev, set Node >=22.5.0 in package.json engines, and configured DATA_DIR=/app/data in render.yaml.
- D024: Hardened per-IP rate limiting middleware in app.ts to prioritize cf-connecting-ip, strip downstream proxy IPs from x-forwarded-for, and strip ephemeral client ports to ensure robust HTTP 429 rate limit enforcement behind Cloudflare and Render reverse proxies.
- D025: Verified DevRelay gateway via MCP get_challenges; call succeeded and retrieved active Week 3 challenge (ID 81), confirming ACTIVE status.
- D026: Implemented per-directory manifest slices for canopy mount and cat with on-demand directory expansion, slashing initial mount transfer to 767 bytes (0.7 KiB). Automated 7-iteration benchmark and created scripts/check-claims.ts verifying every number in README and POST_FACTS against docs/benchmark-results.json in verification gate 7.
- D027: Conducted empirical 5-run bakeoff between models/gemma-4-26b-a4b-it and models/gemma-4-31b-it (documented in docs/bakeoff.md). Gemma 26b achieved 100% first-try schema validity (p50: 13,705 ms) while 31b achieved only 80% validity (p50: 24,200 ms with p95 at 99,952 ms and a degraded fallback). Added reasoning thought stripping (<thought>/<think>) to derived.ts to protect JSON parsing against Gemma thinking blocks. Implemented background cache warmer on boot pre-warming 5 demo items (en/bn digests and 3 key architectural why files), cutting first-user digest latency from ~13.7s cold to ~4ms warm (3,400x speedup), backed by 60s server-side timeout guards and visible progressive timers with 45s AbortController in the Web UI.
- D028: Integrated Sentry OpenTelemetry GenAI agent tracing and privacy protections into DerivedService and SentryClient. Tracked four explicit agent personas (CanopyDigestAgent, CanopyWhyAgent, CanopyCommitAgent, CanopySummaryAgent) with semantic attributes (gen_ai.system, gen_ai.request.model, prompt/completion tokens, latency, cache hit/miss, retries, and degraded flags). Enforced strict privacy by scrubbing client IP addresses and stripping diff/payload bodies from Sentry events and spans. Created scripts/trace-demo.ts (npm run trace:demo) generating 20 varied scenario traces.
- D029: Built scripts/verify-ollama.ts (npm run verify:ollama) to probe Ollama local LLM readiness at http://localhost:11434 with 3s timeout. Because Ollama daemon is not present on the current runner environment, verified graceful offline handling and generated docs/ollama-results.json documenting offline status and explicit developer setup instructions for local open-source inference without failing CI.
- D030: Verified TINKER_API_KEY secret status; key is absent from developer environment. Per the project secret handling protocol ('If missing, skip only that step, record in PROGRESS.md, and continue. Never print or commit secrets'), skipped Tinker fine-tuning/integration while preserving the active Google AI Studio Gemma 4 (models/gemma-4-26b-a4b-it) inference pipeline.
- D031: Rewrote docs/POST_DRAFT.md following DEV Challenge submission guidelines: 3-sentence hook, prominent live Render URL, raw GitHub URL for docs/demo.gif, collapsible details blocks for benchmark tables and 7-gate verification suite, 'What Went Wrong' analysis covering D007/D023/D024, cold-start bakeoff and boot-time cache warming details, Sentry GenAI agent tracing and privacy protections, and an honest account of pair programming with Antigravity and DevRelay MCP verification. Created draft article directly on DEV via DevRelay MCP (Article ID: 4907817, published: false).
- D032: Upgraded Zod from 3.25.76 to 4.6.7 to resolve high-severity vulnerability GHSA-mrhx-c7xc-m3w5 (memory exhaustion on unbounded collections). Verified all flat Zod schemas compile cleanly without breaking changes and all 48 Vitest unit tests pass 100%, achieving 0 vulnerabilities in `npm audit --omit=dev`.

Enriched Sentry agent tracing with `gen_ai.usage.input_tokens` and `output_tokens` semantic attributes, added explicit instruction in `DEPLOY.md` and `README.md` that traces must be verified by a human checking `Explore > Agents`, consolidated duplicate `Deadline and Commit Record` sections into a single authoritative section with a real UTC commit table, and expanded `scripts/check-claims.ts` to audit all sections of `docs/POST_FACTS.md` and `README.md`.
